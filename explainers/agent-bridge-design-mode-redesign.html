Architecture Decision Record

ADR-0001 — Agent Bridge 2.0: Zero-Install Browser Sidecar & cmux Design Mode

Date2026-09-15 AuthorAntigravity DeciderStevie Gonsalvez Proposed
01

Context & Critique

Agent Bridge was conceived as a rapid bridge between humans and AI coding agents to capture visual feedback and apply code fixes. Today, the project suffers from four critical friction points that stall the feedback loop: high SDK setup barriers, non-deterministic agent interaction via tmux hacks, distorted screenshots from html2canvas, and disconnected code patching.

Forces in tension: Human feedback fidelity vs. Agent automation friction
  • Zero Code Intrusion: Agents must inspect and automate arbitrary web apps without modifying main.tsx.
  • Semantic Visual Feedback: Human tweaks (padding, margins, color) must compute exact CSS diffs.
  • Deterministic Agent Tooling: Clean CLI one-shots and MCP calls must replace brittle tmux send-keys.
  • html2canvas Failure: Client-side canvas re-rendering fails on modern CSS variables, grids, and SVGs.
  • Unclosed Fix Loop: Accepting a suggestion saves a patch hint to disk but never updates source code.
02

Options considered

We evaluated three architectural paths to replicate cmux's browser behavior without native macOS lock-in.

Option A

Incremental Polish (Keep In-App SDK)

Keep in-app SDK requirement, polish the Shadow DOM overlay, and patch html2canvas bugs.

  • Smallest codebase diff
  • Reuses current types
  • Fails on SSR/crashed apps
  • html2canvas remains buggy
  • Setup tax repels users
Effortlow
Fitpoor
Risklow
Option BCHOSEN

Zero-Install CDP Sidecar + Injected Design Mode

Promote Playwright/CDP to default browser. Inject cmux-style 14-color palette, CSS tweaker, and auto-generated CSS diff.

  • Zero project modifications
  • Pixel-perfect CDP screenshots
  • Instant CSS diff handoff
  • Requires Chromium binary
  • Slightly larger runtime
Effortmed
Fithigh
Risklow
Option C

Native Multiplexer App (Tauri / Electron)

Port cmux’s macOS Swift AppKit architecture to cross-platform Tauri or Electron shell.

  • Integrated native terminal
  • Exact cmux look and feel
  • Huge development burden
  • Heavy binary distribution
  • Replaces user's preferred IDE
Effortv.high
Fitmed
Riskhigh
03

Decision

B
We will adopt
Zero-Install CDP Browser Sidecar + Injected cmux Design Mode
Option B delivers the high-speed visual editing and non-stealing automation of cmux across all operating systems without requiring a native desktop multiplexer. By decoupling browser control from application source code, any local or remote web app can be inspected immediately with pixel-perfect native screenshots and structured CSS diff handoffs.

05

Consequences

Positive

  • Zero setup tax: Test any local dev server or live URL without adding packages to package.json.
  • Accurate visual understanding: Native CDP captures eliminate html2canvas styling bugs completely.
  • High-speed resolution: AI agents receive exact CSS diffs and XPath locators instead of vague text.
  • Deterministic tooling: Clean CLI one-shots and MCP tools eliminate brittle tmux scraping.

Negative

  • System requires local Chromium/Playwright binaries installed for standalone browser mode.
  • Requires porting and maintaining the 2,200-line BrowserDesignModeRuntime in TypeScript.

Neutral

  • Retains optional in-app SDK mode for developers who explicitly want embedded dev overlays.
  • Cross-platform support across Linux, macOS, and Windows without platform-specific AppKit code.
